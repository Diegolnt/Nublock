# M1 — Activity Tracker: ventana activa, sesiones, idle, SQLite y `report today`

**Objetivo:** saber en qué app estuviste y cuánto tiempo. DoD: usar el PC 1 hora y que
`nublock report today` cuadre con lo que hiciste.

| Archivo | Qué contiene |
|---|---|
| `src/nublock/tracker/platform/base.py` | `WindowInfo` y la interfaz `ActiveWindowProvider` |
| `src/nublock/tracker/platform/macos.py` | Adapter de macOS (pyobjc + psutil) |
| `src/nublock/tracker/platform/fake.py` | `FakeWindowProvider` para tests |
| `src/nublock/tracker/platform/__init__.py` | `get_window_provider()` elige el adapter según el OS |
| `src/nublock/tracker/tracker.py` | `ActivityTracker`: agrupa ticks en `activity_sessions`, idle, gaps |
| `src/nublock/storage/schema.sql`, `repository.py` | Tablas SQLite y acceso con SQL |
| `src/nublock/timeutils.py` | Fechas ISO 8601 UTC, límites del día local |
| `src/nublock/app.py` | Loop principal (`NublockApp.run`) |
| `src/nublock/report.py` | Agregación y formato del reporte |
| `tests/test_tracker.py`, `test_report.py`, `test_cli.py` | Tests con `FakeWindowProvider` y SQLite en RAM |

Cómo probarlo manualmente:

```bash
source .venv/bin/activate
python -m nublock --config config/config.example.yaml run            # usa el PC; Ctrl+C para parar
python -m nublock report today
sqlite3 ~/Library/Application\ Support/nublock/nublock.db "SELECT * FROM activity_sessions;"
tail -f ~/Library/Logs/nublock/nublock.log                           # en otra terminal (con -v ves cada sesión)
```

Para que funcionen los títulos (y las reglas `title_regex`): System Settings → Privacy & Security →
**Screen Recording** → activa tu terminal (iTerm2/Terminal) y reinicia la terminal.

## 1. Cómo funciona (flujo de un tick)

Cada `poll_interval_seconds` (1 s), `NublockApp.tick()`:

1. `ActivityTracker.tick(now)` pregunta al provider la ventana activa y los segundos sin input.
2. La clasifica (M2) y arma la *key* de la sesión: `(process_name, app_name, título guardado,
   productivity, subcategory, is_idle)`.
3. Si la key es igual a la del tick anterior → la sesión sigue (cada 10 s se escribe `ended_at`
   como *heartbeat*). Si cambió → se cierra la sesión anterior y se abre una nueva fila.
4. Idle: si `idle_seconds >= idle_threshold_seconds`, la sesión nueva es `is_idle=1` y empieza
   retroactivamente donde fue el último input.
5. Gap: si entre ticks pasaron más de `max(10 s, 5 × poll)` (el Mac durmió), la sesión se cierra
   en el último tick visto.

Resultado: **una fila por periodo continuo**, no una por segundo (FR-02).

**Dependency injection:** `ActivityTracker` recibe el provider, el classifier y el repository por
el constructor, en vez de crearlos adentro. Así los tests le pasan un `FakeWindowProvider` y una DB
en RAM, y le dan el tiempo (`now`) explícitamente: no hay que esperar segundos reales.

## 2. pyobjc — llamar APIs nativas de macOS desde Python

**pyobjc** es un *bridge* (puente) entre Python y Objective-C: expone los frameworks de Apple como
módulos Python. Paquetes instalados: `pyobjc-framework-Cocoa` (módulos `AppKit` y `Foundation`) y
`pyobjc-framework-Quartz` (módulo `Quartz`).

**Convención de nombres:** un método Objective-C como `runUntilDate:` se llama en Python
`runUntilDate_(fecha)`: cada `:` se reemplaza por `_` y los argumentos van en orden.

### `AppKit.NSWorkspace`
| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `NSWorkspace.sharedWorkspace()` | El objeto *singleton* que representa el "escritorio" del usuario (apps corriendo, abrir archivos…) | — | `NSWorkspace` |
| `workspace.frontmostApplication()` | La app en primer plano (la que recibe el teclado) | — | `NSRunningApplication` o `None` |

**Importante:** `NSWorkspace` actualiza `frontmostApplication` procesando notificaciones en el *run
loop* del **main thread**. Si nadie lo hace girar, el valor queda congelado. En M1–M2 el tracker
corría en el main thread; desde M5 corre en su propio thread y el main thread hace girar el run
loop (lo hace el tray, o `run_main_loop()` con `--no-tray`). Ver DECISIONS.md #16 y #40.

### `AppKit.NSRunningApplication` (lo que retorna `frontmostApplication()`)
| Método | Retorna |
|---|---|
| `app.localizedName()` | Nombre visible de la app (`NSString`, se usa como `str`), ej. `"iTerm2"`; puede ser `None` |
| `app.processIdentifier()` | El PID (*Process Identifier*) como entero |

### `Foundation.NSRunLoop` y `Foundation.NSDate`
Un **run loop** es el ciclo de eventos de un thread en macOS: espera eventos (notificaciones,
timers, input) y los despacha. Si nadie lo "hace girar", las notificaciones quedan pendientes.

| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `NSRunLoop.currentRunLoop()` | El run loop del thread actual | — | `NSRunLoop` |
| `run_loop.runUntilDate_(date)` | Procesa eventos hasta esa fecha | `date`: `NSDate` | `None` |
| `NSDate.dateWithTimeIntervalSinceNow_(seconds)` | Una fecha `seconds` segundos en el futuro | `float` | `NSDate` |

`run_main_loop(stop)` (en `macos.py`) llama `runUntilDate_` en tramos de 0,25 s hasta que se pida
detener la app. (En M1–M2 el provider lo hacía girar ~10 ms antes de cada lectura.)

### `Quartz` (CoreGraphics)
| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `Quartz.CGWindowListCopyWindowInfo(option, relativeToWindow)` | Lista información de las ventanas, ordenadas de adelante hacia atrás | `option`: flags combinables con `\|`: `kCGWindowListOptionOnScreenOnly` (solo visibles) y `kCGWindowListExcludeDesktopElements` (sin íconos del escritorio). `relativeToWindow`: `kCGNullWindowID` (= todas) | Lista de dicts (o `None`) |
| claves de cada dict | `kCGWindowOwnerPID` (PID dueño), `kCGWindowOwnerName` (nombre de la app), `kCGWindowLayer` (0 = ventana normal; > 0 = menús, overlays), `kCGWindowName` (título; **solo con permiso Screen Recording**) | — | — |
| `Quartz.CGPreflightScreenCaptureAccess()` | Consulta si este proceso tiene permiso **Screen Recording**, sin mostrar el diálogo | — | `bool` |
| `Quartz.CGEventSourceSecondsSinceLastEventType(stateID, eventType)` | Segundos desde el último evento de input | `stateID`: `kCGEventSourceStateCombinedSessionState` (todo el input de la sesión del usuario); `eventType`: `kCGAnyInputEventType` (cualquier tecla, click o movimiento) | `float` |

Con eso `MacOSWindowProvider` implementa:
- `get_active_window() -> WindowInfo | None`: app activa + PID + nombre del ejecutable + título.
- `get_idle_seconds() -> float`: segundos sin input (idle detection, FR-03).

## 3. psutil — información de procesos

| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `psutil.Process(pid)` | Objeto que representa un proceso del OS | `pid: int` | `Process` (lanza `psutil.NoSuchProcess` si no existe) |
| `process.name()` | Nombre del ejecutable, ej. `"Google Chrome"`, `"iTerm2"` | — | `str` |
| `psutil.NoSuchProcess`, `psutil.AccessDenied` | Excepciones: el proceso ya terminó / el OS no deja leerlo | — | — |

Ese nombre es el `process_name` que comparan los matchers `process` del config. Para ver el de una
app: `ps -axo comm | grep -i <app>` (la última parte de la ruta).

## 4. Interfaces y fakes (`typing.Protocol`, `dataclass`)

- **`typing.Protocol`**: define una interfaz por *structural typing* ("duck typing" con tipos):
  cualquier clase que tenga `get_active_window()` y `get_idle_seconds()` con esas firmas es un
  `ActiveWindowProvider`, sin heredar de nada. `MacOSWindowProvider` y `FakeWindowProvider` lo
  cumplen.
- **`@dataclass(frozen=True) class WindowInfo`**: contenedor inmutable de `process_name`, `pid`,
  `app_name`, `window_title`. `frozen` permite compararlo con `==` de forma segura.
- **`FakeWindowProvider(window, idle_seconds)`**: el test asigna `provider.window = ...` y
  `provider.idle_seconds = ...` antes de cada tick.
- **`get_window_provider()`**: usa `sys.platform` y hace el `import` de `macos.py` dentro de la
  función (*lazy import*) para que en otros OS no falle por no tener pyobjc.

## 5. `sqlite3` (stdlib) — la base de datos

SQLite es una base de datos SQL (*Structured Query Language*) en un solo archivo, sin servidor.

| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `sqlite3.connect(path)` | Abre (o crea) la DB. `":memory:"` crea una DB en RAM (tests) | ruta | `Connection` |
| `conn.row_factory = sqlite3.Row` | Las filas se leen como `row["columna"]` en vez de por índice | — | — |
| `conn.execute(sql, params)` | Ejecuta una sentencia. Los `?` son *placeholders*: sqlite3 inserta `params` escapados (evita **SQL injection**) | `sql: str`, `params: tuple` | `Cursor` |
| `conn.executescript(sql)` | Ejecuta varias sentencias separadas por `;` (el schema) | `str` | `Cursor` |
| `with conn:` | Transacción: *commit* al salir del bloque, *rollback* si hubo excepción | — | — |
| `cursor.lastrowid` | `id` de la última fila insertada | — | `int \| None` |
| `cursor.rowcount` | Filas afectadas por un `UPDATE`/`DELETE` | — | `int` |
| `cursor.fetchall()` / `fetchone()` | Todas las filas / la siguiente | — | `list[Row]` / `Row \| None` |
| `conn.close()` | Cierra la conexión | — | `None` |

SQL usado:
- `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`: crea solo si no existe (se puede
  correr en cada arranque). `CHECK (...)`: restricción que la DB valida en cada insert.
- `INSERT INTO t (cols) VALUES (?, ...)`, `UPDATE t SET col = ? WHERE id = ?`,
  `DELETE FROM t WHERE ...`, `SELECT * FROM t WHERE ... ORDER BY started_at`.
- `COALESCE(a, b)`: retorna `a` si no es NULL, si no `b` (sesiones aún sin `ended_at`).
- `PRAGMA journal_mode=WAL`: *Write-Ahead Logging*: los cambios se escriben primero a un archivo
  `-wal`, lo que permite leer (`report`) mientras otro proceso escribe (`run`).
- `PRAGMA busy_timeout=5000`: si la DB está bloqueada, esperar hasta 5000 ms en vez de fallar.

Las fechas son `TEXT` en ISO 8601 UTC con el mismo formato, así que comparar strings
(`started_at < ?`) equivale a comparar fechas.

`Repository` (nuestra clase) encapsula todo el SQL: `open_session()`, `set_session_end()`,
`sessions_between(start, end)`, `delete_sessions_before(cutoff)`, `record_intervention()`.

### `importlib.resources` (stdlib)
- `resources.files("nublock.storage")` → objeto tipo ruta a la carpeta del paquete instalado;
  `.joinpath("schema.sql").read_text("utf-8")` → contenido del archivo como `str`. Funciona aunque
  el paquete esté instalado en otro lugar (no depende del directorio actual).

## 6. `datetime` y `time` (stdlib)

| API | Qué hace | Retorna |
|---|---|---|
| `datetime.now(UTC)` | Hora actual con timezone UTC (*Coordinated Universal Time*) | `datetime` *aware* |
| `dt.astimezone()` | Sin argumento: convierte a la timezone local del sistema. Con un `datetime` *naive* (sin tz) lo interpreta como hora local | `datetime` |
| `dt.astimezone(UTC)` | Convierte a UTC | `datetime` |
| `dt.isoformat(timespec="milliseconds")` | `"2026-10-29T18:42:27.262+00:00"` (reemplazamos `+00:00` por `Z`) | `str` |
| `datetime.fromisoformat(text)` | Inverso; desde Python 3.11 acepta el sufijo `Z` | `datetime` |
| `datetime.combine(date, time.min)` | Une una fecha con una hora (`time.min` = 00:00) | `datetime` |
| `timedelta(seconds=..., days=...)` | Duración; se suma/resta a `datetime` | `timedelta` |
| `td.total_seconds()` | Duración en segundos | `float` |
| `dt.date()`, `dt.time()`, `dt.weekday()` | Parte de fecha, parte de hora, día de semana (lunes=0) | `date`, `time`, `int` |
| `date.today()` | Fecha local de hoy | `date` |
| `time.sleep(seconds)` (módulo `time`) | Pausa el thread | `None` |
| `time.monotonic()` | Reloj que nunca retrocede (no afectado por cambios de hora); para medir duraciones (`--duration`) | `float` |

Nuestras funciones (`timeutils.py`): `utc_now()`, `to_iso(dt)`, `from_iso(text)`,
`local_day_bounds(day) -> (inicio_utc, fin_utc)` (respeta horario de verano), y
`overlap_seconds(start, end, window_start, window_end)` (cuánto de una sesión cae dentro del día).

## 7. `signal` (stdlib) — terminar limpio

| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `signal.signal(signalnum, handler)` | Registra qué función se llama cuando el OS envía esa señal | `signal.SIGTERM` (petición de terminar, ej. `kill`), `handler(signum: int, frame: FrameType \| None)` | El handler anterior (lo restauramos al salir) |

- **Ctrl+C** envía `SIGINT`, que Python convierte en la excepción `KeyboardInterrupt`.
- En ambos casos `NublockApp.run()` sale del loop y en el `finally` cierra la sesión abierta con
  `tracker.close(now)`, así no queda una fila sin `ended_at`.
- `types.FrameType` es solo el tipo del parámetro `frame` (para el type hint).
- `collections.abc.Callable[[], datetime]` es el tipo de `clock`: "función sin argumentos que
  retorna un `datetime`". En tests se inyecta un `FakeClock`.

## 8. Reporte (`report.py`)

- `build_daily_report(day, sessions, day_start, day_end)` recorta cada sesión al día
  (`overlap_seconds`), separa idle, y suma por productivity, por (productivity, subcategory) y por
  app. Retorna un `DailyReport` (dataclass).
- `format_report(report) -> str` arma el texto; `format_duration(seconds) -> str` da `1h 02m`,
  `5m 12s` o `42s`.

Herramientas de Python usadas:

| API | Qué hace | Retorna |
|---|---|---|
| `collections.defaultdict(float)` | Dict donde una key nueva vale `0.0` automáticamente (para ir sumando) | `defaultdict` |
| `dataclasses.field(default_factory=dict)` | Default mutable seguro en una dataclass (un dict nuevo por instancia) | — |
| `max(iterable, key=fn)` | Elemento con mayor `fn(x)`; con `cats.__getitem__` = la categoría con más segundos | elemento |
| `list.sort(key=fn, reverse=True)` / `sorted(...)` | Ordena (de mayor a menor) | `None` / nueva lista |
| `divmod(a, b)` | `(a // b, a % b)`, para horas/minutos/segundos | `tuple` |
| `enumerate(it, start=1)` | Pares `(índice, elemento)` empezando en 1 | iterador |
| f-strings con formato: `f"{x:<14}"`, `f"{x:>9}"`, `f"{x:5.1f}"`, `f"{n:02d}"` | Alinear a la izquierda/derecha con ancho fijo, decimales, ceros a la izquierda | `str` |
