# M2 — Classification + Rules: categorías, timers, `daily_limit`, `schedule`, notificaciones

**Objetivo:** clasificar cada app/ventana como `productive` / `neutral` / `distracting` (+ una
subcategoría) y hacer cumplir reglas del usuario con notificaciones. DoD: tests unitarios del
classifier y del rules engine con fakes, y una notificación al pasar un límite.

| Archivo | Qué contiene |
|---|---|
| `src/nublock/classifier/classifier.py` | `Classifier`, `Classification`, `UNCATEGORIZED` |
| `src/nublock/rules/timers.py` | `DailyTimers` (FR-20) y `matches_target()` |
| `src/nublock/rules/engine.py` | `RulesEngine`, `is_within_schedule()` |
| `src/nublock/events.py` | `ActivityEvent`, `RuleViolation` |
| `src/nublock/interventions/notifier.py` | `MacOSNotifier` (osascript), `LogNotifier` |
| `src/nublock/app.py` | Une tracker → timers → rules → notifier; aplica `observe_only` |
| `tests/test_classifier.py`, `test_rules.py`, `test_app.py` | Tests con fakes |

Cómo probarlo manualmente:

1. Copia el ejemplo y edítalo: `cp config/config.example.yaml ~/Library/Application\ Support/nublock/config.yaml`.
2. Pon `observe_only: false` y agrega una regla corta para ver la notificación, por ejemplo:
   ```yaml
   rules:
     - id: prueba
       type: daily_limit
       target: { process: "Finder" }
       limit_minutes: 0.5
       action: notify
   ```
3. `python -m nublock -v run`, abre Finder 30 s → aparece una notificación de macOS ("Script
   Editor" puede pedir permiso de notificaciones la primera vez).
4. `sqlite3 ~/Library/Application\ Support/nublock/nublock.db "SELECT * FROM interventions;"`
5. Vuelve a `observe_only: true`: la violación solo aparece en `~/Library/Logs/nublock/nublock.log`.

## 1. Classifier (FR-10..13)

- **`Classifier(rules)`**: recibe la lista `classification_rules` del config y compila las regex
  **una sola vez** (classify se llama cada segundo).
- **`classifier.classify(window) -> Classification`**: recorre las reglas **en orden** y retorna la
  primera que coincide. Si ninguna coincide: `UNCATEGORIZED = Classification("neutral",
  "uncategorized")`.
- Matchers:
  - `process`: igualdad exacta, case-insensitive, contra `window.process_name`.
  - `title_regex`: `pattern.search(window.window_title)`; si no hay título (`None`), no coincide.

### `re` (stdlib) — regular expressions
| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `re.compile(pattern)` | Compila la regex para reusarla | `pattern: str` | `re.Pattern[str]` (lanza `re.error` si es inválida) |
| `pattern.search(text)` | Busca la regex en **cualquier parte** del texto | `text: str` | `re.Match` o `None` |
| (comparación) `pattern.match(text)` | Solo al **inicio** del texto (no lo usamos) | | `re.Match` o `None` |
| `(?i)` dentro de la regex | *Inline flag*: ignora mayúsculas/minúsculas | | |
| `\\.` en YAML entre comillas dobles | Se lee como `\.` = un punto literal (en regex `.` = cualquier carácter) | | |

### `str.casefold()`
Versión "agresiva" de `lower()` pensada para comparar sin importar mayúsculas (maneja casos
Unicode como `ß`). **Retorna** un `str`. Se usa en el matcher `process` y en `matches_target`.

### `@dataclass(frozen=True)` en `Classification` y `_CompiledRule`
Inmutables y comparables con `==` (los tests hacen `assert result == UNCATEGORIZED`).

## 2. Timers diarios (FR-20) — `rules/timers.py`

- **`DailyTimers`** guarda segundos acumulados **hoy** por `(process_name, productivity,
  subcategory)` en un `defaultdict(float)`.
  - `add_event(day, event)`: suma `event.seconds` (ignora idle). Si `day` cambió, reinicia todo.
  - `load_sessions(day, sessions, day_start, day_end)`: al arrancar la app suma lo que ya estaba
    guardado hoy en SQLite (así reiniciar la app no resetea tus límites).
  - `seconds_for(target) -> float`: suma de todas las keys que cumplen el target.
- **`matches_target(target, process_name, productivity, subcategory) -> bool`**: `True` si se
  cumplen **todas** las keys definidas en el target (AND); las keys `None` no se revisan.
- `collections.abc.Iterable`: tipo "cualquier cosa que se pueda recorrer con `for`".

## 3. Rules Engine (FR-21) — `rules/engine.py`

**`RulesEngine(rules, cooldown_seconds=30)`** y **`engine.evaluate(event, timers, now_local) ->
list[RuleViolation]`**: retorna solo las violaciones **nuevas** de este tick.

Una regla está "violada" en un tick si: no estás idle **y** la actividad actual cumple el `target`
**y**:
- `daily_limit`: `timers.seconds_for(target) >= limit_minutes * 60`.
- `schedule`: el día local está en `days` y la hora está en `[start, end)`; si `start > end` el rango
  cruza medianoche (ej. 22:00–02:00).

**Edge-triggered + cooldown:** se avisa cuando una regla *pasa* de no violada a violada (no en cada
tick). Un `set` guarda qué reglas estaban violadas el tick anterior (`add`/`discard`), y un dict
guarda cuándo se avisó por última vez cada regla; si volviste al target hace menos de
`cooldown_seconds`, no se repite el aviso (evita spam al hacer alt-tab).

APIs usadas:

| API | Qué hace | Retorna |
|---|---|---|
| `isinstance(rule, DailyLimitRule)` | ¿Es de esa clase? Distingue los tipos de regla del *union* | `bool` |
| `datetime.weekday()` | Día de la semana, lunes = 0 | `int` |
| `WEEKDAYS[i]` | Convierte 0..6 a `"mon"`..`"sun"` (tupla en `config.py`) | `str` |
| `time` comparaciones (`start <= t < end`) | Los objetos `datetime.time` se comparan como horas | `bool` |
| `f"{rule.start:%H:%M}"` | Formatea un `time` dentro de un f-string con códigos de `strftime` | `str` |
| `f"{x:g}"` | Formato numérico "general": `1.0` → `1`, `0.5` → `0.5` | `str` |
| `datetime.timezone(timedelta(hours=-3))` (tests) | Timezone de offset fijo (UTC−3) para que los tests no dependan del OS | `timezone` |

### Eventos — `events.py`
- **`ActivityEvent`**: `at` (UTC), `seconds` (desde el tick anterior), `window`, `classification`,
  `is_idle`. Lo produce `ActivityTracker.tick()`.
- **`RuleViolation`**: `at`, `rule_id`, `action`, `mode`, `message`. Lo produce el rules engine.

## 4. Observe-only e interventions — `app.py`

`NublockApp.tick()`: `tracker.tick()` → `timers.add_event()` → `rules.evaluate()` → por cada
violación `_handle_violation()`:
- **`observe_only: true`** (default, FR-24): solo `logger.info(...)`. No notifica ni escribe en
  `interventions`. Sirve para medir tu *baseline* la primera semana.
- **`observe_only: false`**: `notifier.notify("Nublock", mensaje)` + fila en `interventions`
  (`trigger="rule:<id>"`, `level=1`). En M2, `warn` y `block` también se ejecutan como `notify`
  (llegan en M6).

## 5. Notificaciones — `interventions/notifier.py`

### `subprocess.run` (stdlib)
| Argumento | Qué hace |
|---|---|
| `args: list[str]` | Programa y argumentos, **como lista** (sin pasar por un shell: nada se interpreta como comando) |
| `capture_output=True` | Guarda stdout/stderr en vez de imprimirlos |
| `text=True` | stdout/stderr como `str` en vez de `bytes` |
| `timeout=5` | Si tarda más, lanza `subprocess.TimeoutExpired` |
| `check=False` | No lanzar excepción si el exit code ≠ 0 (lo revisamos a mano) |
| **Retorna** | `CompletedProcess` con `.returncode` (`int`), `.stdout`, `.stderr` |
| **Lanza** | `OSError` si el programa no existe; `TimeoutExpired` |

### `osascript` y AppleScript
`osascript` es un programa incluido en macOS que ejecuta AppleScript.
- `-e "<línea>"`: una línea del script.
- `on run argv ... end run`: el script recibe los argumentos extra de la línea de comandos en la
  lista `argv`. Pasamos título y mensaje como argumentos (no los pegamos dentro del código del
  script), así un mensaje con comillas no puede romper ni inyectar código.
- `display notification <texto> with title <título>`: muestra una notificación del sistema.

### Clases
- **`Notifier`** (`Protocol`): cualquier clase con `notify(title, message) -> None`.
- **`MacOSNotifier`**: usa `osascript`; si falla, loguea un warning (nunca tumba el tracker).
- **`LogNotifier`**: fallback para otros OS, escribe en el log.
- **`get_notifier()`**: elige según `sys.platform`.
- En tests: **`RecordingNotifier`** (`tests/helpers.py`) guarda los mensajes en una lista.

## 6. Cómo están testeados (todo con fakes, sin OS real)

- `tests/test_classifier.py`: `process` case-insensitive y exacto, `title_regex` (search, flag
  `(?i)`, título `None`), orden de reglas (la primera gana; invertir el orden invierte el
  resultado), `uncategorized`.
- `tests/test_rules.py`: `Simulation` alimenta timers + engine un tick por segundo con un reloj
  propio. Cubre: `daily_limit` dispara una sola vez justo al llegar al límite, no fuera del target,
  re-avisa después del cooldown pero no en un alt-tab rápido, nunca en idle; `schedule` con
  bordes (inicio inclusivo, fin exclusivo), sábado, rango que cruza medianoche, inicio del horario
  con la app ya abierta; reglas independientes.
- `tests/test_app.py`: integración `FakeWindowProvider` + `FakeClock` + SQLite en RAM +
  `RecordingNotifier`: notificación al pasar el límite con `observe_only: false`, ninguna con
  `observe_only: true`, timers recargados desde la DB al reiniciar, retención de datos.
