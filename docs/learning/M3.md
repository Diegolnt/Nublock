# M3 — Attention Monitor: cámara, face landmarks, head pose, calibración y state machine

**Objetivo:** estimar con la cámara, **procesando todo en memoria**, si miras la pantalla, a otro
lado, hacia abajo o si no estás. DoD: en el debug view los estados cambian correctamente al mirar
la pantalla, a la izquierda, hacia abajo y al salir.

Cómo probarlo manualmente (necesita permiso **Camera** para tu terminal):

```bash
source .venv/bin/activate
python -m nublock calibrate          # sigue las instrucciones: centro y 4 esquinas de cada monitor
python -m nublock attention-debug    # mira la pantalla, a la izquierda, abajo, sal del cuadro
```

Arriba a la izquierda verás el estado estable y el raw. Abajo, yaw/pitch/gaze. Al girar la cabeza
1 s el estado **no** cambia (debounce); si te quedas 2 s mirando a otro lado, sí cambia.

## 1. El pipeline de un frame

```
cámara (BGR 1280×720) -> to_rgb(): reducir a 640 px + BGR→RGB -> FaceLandmarker
   -> FaceObservation(yaw, pitch, roll, gaze_down) -> classify_observation() -> estado raw
   -> AttentionStateMachine (debounce) -> AttentionTransition -> event bus -> core
```

**Privacidad:** el frame solo existe como variable local dentro de `AttentionMonitor.step()`.
No se guarda en atributos, no se loguea y no se escribe a disco; lo que sale del monitor son
estados con timestamps. `tests/test_monitor.py::test_privacy_no_frames_written_or_kept` lo verifica:
hace que `cv2.imwrite` falle si alguien lo llama, corre el monitor con `FakeCamera` y revisa que no
se haya creado ningún archivo y que ningún objeto guarde un `numpy.ndarray`.

## 2. numpy — arrays (el formato de los frames)

Un frame es un `numpy.ndarray` de forma `(alto, ancho, 3)` y tipo `uint8` (enteros 0–255, uno por
canal de color).

| API | Qué hace | Retorna |
|---|---|---|
| `np.zeros(shape, dtype=np.uint8)` / `np.full(shape, valor, dtype)` | Array lleno de ceros / de `valor` (frames sintéticos para tests) | `ndarray` |
| `array.shape` | Dimensiones, ej. `(720, 1280, 3)` | `tuple[int, ...]` |
| `np.asarray(x, dtype=float)` | Convierte a array sin copiar si no hace falta | `ndarray` |
| `array[:3, :3]` | *Slicing*: filas 0–2, columnas 0–2 (la rotación 3×3 dentro de la matriz 4×4) | `ndarray` |

| `numpy.typing.NDArray[np.uint8]` | Type hint "array de uint8"; lo usamos como alias `Frame` | — |

teléfono usa un recorte a resolución completa (ver M4.md).

## 4. MediaPipe Face Landmarker (Tasks API)

MediaPipe es una librería de Google con modelos de ML (*Machine Learning*) que corren **on-device**
(en tu CPU, sin internet). El modelo viene en el archivo `models/face_landmarker.task`.

| API | Qué hace | Argumentos | Retorna |
|---|---|---|---|
| `mp_python.BaseOptions(model_asset_path=...)` | Opciones comunes: dónde está el modelo | ruta (`str`) | `BaseOptions` |
| `vision.FaceLandmarkerOptions(...)` | Configuración del landmarker (ver tabla siguiente) | keywords | opciones |
| `vision.FaceLandmarker.create_from_options(options)` | Carga el modelo y crea el detector | opciones | `FaceLandmarker` |
| `mp.Image(image_format=mp.ImageFormat.SRGB, data=rgb)` | Envuelve el array RGB en el formato de MediaPipe | formato, `ndarray` | `mp.Image` |
| `landmarker.detect_for_video(image, timestamp_ms)` | Analiza un frame de un video. `timestamp_ms` debe ser **estrictamente creciente** (usamos `time.monotonic()`) | imagen, `int` | `FaceLandmarkerResult` |
| `landmarker.close()` | Libera los recursos del modelo | — | `None` |

Opciones usadas (`FaceLandmarkerOptions`):

| Argumento | Valor | Qué hace |
|---|---|---|
| `running_mode` | `vision.RunningMode.VIDEO` | Frames en secuencia: usa tracking entre frames (más rápido y estable que `IMAGE`) |
| `num_faces` | `1` | Solo la cara del usuario |
| `output_face_blendshapes` | `True` | 52 coeficientes 0–1 de expresión/mirada (ej. `eyeLookDownLeft`) |
| `output_facial_transformation_matrixes` | `True` | Matriz 4×4 con la rotación/traslación de la cabeza |
| `min_face_detection_confidence` / `min_face_presence_confidence` / `min_tracking_confidence` | `0.5` | Scores mínimos para detectar, mantener y seguir la cara |

`FaceObservation.face_box` = `(min(x), min(y), max(x), max(y))` de los 478 landmarks: el
rectángulo de la cara (normalizado), que ubica el recorte donde se busca el teléfono.

`FaceLandmarkerResult` (lo que retorna `detect_for_video`):
- `result.face_landmarks`: lista (una por cara) de 478 puntos con `.x`, `.y` (normalizados 0–1) y `.z`.
- `result.face_blendshapes`: lista (una por cara) de `Category` con `.category_name` (`str`) y `.score` (`float`).
- `result.facial_transformation_matrixes`: lista (una por cara) de matrices 4×4.
- Listas vacías = no hay cara → nuestro `analyze()` retorna `None` → estado `ABSENT`.

`os.environ.setdefault("GLOG_minloglevel", "2")` reduce los logs internos de MediaPipe (variable de
entorno de la librería de logging que usa, *glog*). `setdefault` solo la define si no existía.

## 5. Head pose: de matriz de rotación a yaw/pitch/roll

Una **matriz de rotación** 3×3 `R` describe la orientación de la cabeza. Los **ángulos de Euler**
la expresan como tres giros: **yaw** (eje Y, izquierda/derecha), **pitch** (eje X, arriba/abajo) y
**roll** (eje Z, inclinar la cabeza hacia un hombro). Con la convención Z-Y-X:

```python
pitch = atan2(R[2,1], R[2,2])
yaw   = atan2(-R[2,0], hypot(R[2,1], R[2,2]))
roll  = atan2(R[1,0], R[0,0])
```

| Función (`math`) | Qué hace | Retorna |
|---|---|---|
| `math.atan2(y, x)` | Ángulo (radianes) del punto (x, y); maneja bien los cuadrantes y x = 0 | `float` |
| `math.hypot(a, b)` | √(a² + b²) | `float` |
| `math.degrees(rad)` | Radianes → grados | `float` |

El **signo** del pitch depende del modelo y de la cámara; por eso la calibración mide
`down_sign` (si al mirar las esquinas inferiores el pitch sube o baja). Los tests verifican
`euler_from_matrix` con rotaciones conocidas de 25° en cada eje.

## 6. Zona calibrada y estado raw (`zone.py`)

- **`CalibrationZone(yaw_min, yaw_max, pitch_min, pitch_max, down_sign)`**: rangos medidos al mirar
  los puntos de calibración. `to_dict()` usa `dataclasses.asdict` (dataclass → `dict`) y
  `from_dict()` es un `@classmethod` (un constructor alternativo que recibe la clase como `cls`).
- **`classify_observation(observation, zone, config, previous) -> AttentionState`**:
  1. Sin cara → `ABSENT`.
  2. yaw fuera de `[yaw_min − margen, yaw_max + margen]` → `LOOKING_AWAY`.
  3. pitch más allá del borde "abajo" → `LOOKING_DOWN`; más allá del borde "arriba" → `LOOKING_AWAY`.
  4. Cabeza al frente pero `gaze_down ≥ gaze_down_threshold` → `LOOKING_DOWN` (señal secundaria).
  5. Si no → `FOCUSED`.
- **Hysteresis**: si el estado anterior no era FOCUSED, los márgenes se achican `hysteresis_deg`.
  Entrar a "distraído" y volver a "focus" usan umbrales distintos, así un ángulo justo en el borde
  no hace parpadear el estado.

## 7. Debounce (`state_machine.py`)

- **`AttentionStateMachine(debounce_seconds)`** con **`update(raw, now) -> AttentionTransition | None`**:
  un estado raw nuevo es solo un *candidato*; recién si se mantiene `debounce_seconds` (2 s) se
  convierte en el estado estable y se emite una `AttentionTransition`. Parpadear o girar la cabeza
  1 s no genera transición (AC de FR-34, testeado).
- `PAUSED` y `CAMERA_UNAVAILABLE` son hechos, no percepciones: se aplican sin esperar.
- `AttentionTransition(previous, state, started_at, previous_confidence)`: `started_at` es cuándo
  empezó el candidato; `previous_confidence` es la fracción de frames que coincidieron con el
  estado anterior (se guarda en `attention_events.confidence`).

### `enum.StrEnum` (Python 3.11+)
`class AttentionState(StrEnum)`: un *enum* (conjunto fijo de constantes con nombre) cuyos miembros
también son `str`. `AttentionState.PHONE == "PHONE"` es `True`, así se guarda directo en SQLite.
`frozenset({...})` es un set inmutable (`DISTRACTED_STATES`).

## 8. Calibración (`calibration.py`)

- **`run_calibration(camera, analyzer, monitors, frame_width, ask=input, say=print)`**: para cada
  monitor pide mirar centro y 4 esquinas (`ask` muestra el texto y espera Enter), junta ~2 s de
  muestras `(yaw, pitch)` y llama `compute_zone`. `ask`/`say` se inyectan: en tests se reemplazan
  por funciones falsas.
- **`compute_zone(samples) -> CalibrationZone`**: mediana por punto (resistente a valores raros) y
  rango de las medianas. Lanza `CalibrationError` si hay menos de 2 puntos con cara.
- **`save_zone(zone, path)` / `load_zone(path)`**: JSON con solo números.

| API | Qué hace | Retorna |
|---|---|---|
| `statistics.median(valores)` | Valor del medio (ordenados) | número |
| `statistics.mean(valores)` | Promedio | `float` |
| `json.dumps(obj, indent=2)` / `json.loads(texto)` | Objeto Python ↔ texto JSON (*JavaScript Object Notation*) | `str` / objeto |
| `input(prompt)` | Muestra `prompt` y lee una línea del teclado | `str` |

## 9. El thread de cámara (`monitor.py`)

- **`AttentionPipeline(config, zone, analyzer, phone_detector)`** con
  **`process(rgb, now) -> (FaceObservation | None, AttentionState)`**: compartido por el monitor y
  el debug view (el detector de teléfono se explica en M4.md).
- **`AttentionMonitor(config, camera, pipeline_factory, publish, clock)`**:
  - `set_active(bool)`: el core la prende solo cuando corresponde (focus session, sin pausa, sin
    app exenta). Apagado = cámara liberada y estado `PAUSED`.
  - `step()`: una iteración (abre la cámara si hace falta, lee, analiza, descarta el frame).
  - `run()`: el *target* del thread: llama `step()` ~`process_fps` veces por segundo hasta `stop()`.
  - Si la cámara no abre o falla una lectura → `CAMERA_UNAVAILABLE` y reintento cada
    `camera_retry_seconds` (FR-36). Una excepción se loguea y el resto de Nublock sigue (NFR-06).
  - `pipeline_factory`: los modelos se cargan recién la primera vez que la cámara se activa.

| API (`threading`) | Qué hace | Retorna |
|---|---|---|
| `threading.Event()` | Flag thread-safe: `set()` lo prende, `clear()` lo apaga, `is_set()` lo consulta | `Event` |
| `event.wait(timeout)` | Espera hasta que se prenda o pase `timeout` (un `sleep` que despierta al instante con `stop`) | `bool` |
| `threading.Thread(target=fn, name=..., daemon=True)` | Crea un thread que ejecutará `fn`; *daemon* = no impide que el programa termine | `Thread` |
| `thread.start()` / `thread.join(timeout)` | Lo inicia / espera a que termine | `None` |
| `time.monotonic()` | Reloj que nunca retrocede, para medir intervalos | `float` |
