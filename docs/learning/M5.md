# M5 — Threads + event bus, system tray y dashboard local

**Objetivo:** usar Nublock sin terminal: un ícono en la barra de menú que refleja el estado y un
dashboard en el navegador. DoD: el dashboard muestra el día y el tray refleja el estado.

| Archivo | Qué contiene |
|---|---|
| `src/nublock/app.py` | `NublockApp`: arma los threads y maneja Ctrl+C/SIGTERM |
| `src/nublock/core.py` | `Core`: consume el event bus (rules, interventions, focus, atención) |
| `src/nublock/events.py` | Eventos, comandos y `EventBus` (`queue.Queue`) |
| `src/nublock/live_state.py` | `LiveState` / `Snapshot`: estado en vivo para la UI |
| `src/nublock/ui/tray.py` | `Tray` (pystray + Pillow) |
| `src/nublock/dashboard/server.py`, `data.py`, `templates/` | FastAPI + Jinja2 |
| `tests/test_core.py`, `test_dashboard.py`, `test_tray.py` | Tests |

Cómo probarlo manualmente:

```bash
python -m nublock run              # aparece el ícono en la barra de menú
open http://127.0.0.1:8765         # el dashboard
```

- Cambia de app: el menú del tray muestra la app actual y los timers del día.
- Dashboard → "Apps sin clasificar" → clasifica una → sus sesiones nuevas usan esa categoría.
- Inicia/termina una focus session desde el tray o el dashboard.
- Ctrl+C en la terminal o "Salir" en el tray: todo se cierra limpio.

## 1. Arquitectura: threads + event bus (PRD sección 9)

```
main thread : Tray.run()  (o run_main_loop() con --no-tray) — hace girar el run loop de macOS
tracker     : ActivityTracker.tick() cada 1 s    ──ActivityEvent────────┐
attention   : AttentionMonitor.run() ~8 FPS      ──AttentionTransition──┤
tray/dashboard: clicks                           ──comandos─────────────┤
                                                                         ▼
core        : bus.get() -> Core.handle(evento); Core.tick() cada 0,2 s ── SQLite, notificaciones
dashboard   : uvicorn en 127.0.0.1 (lee SQLite + LiveState)
```

- Los módulos no se llaman entre threads: **publican eventos** en el bus y un solo thread (core)
  los procesa en orden. Así no hay dos threads tocando las mismas estructuras a la vez.
- `Core` no sabe de threads: `handle(evento)` y `tick()` se testean llamándolos directo, y
  `NublockApp.tick()` corre una iteración síncrona de todo (lo usan los tests).
- En macOS el main thread debe hacer girar el run loop: es lo que mantiene actualizada la app
  activa para el tracker (DECISIONS.md #40) y lo que necesita el ícono del tray.

| API | Qué hace | Retorna |
|---|---|---|
| `queue.Queue()` | Cola FIFO (*first in, first out*) thread-safe | `Queue` |
| `q.put(item)` | Agrega (nunca bloquea si no tiene límite) | `None` |
| `q.get(timeout=s)` | Saca el siguiente; espera hasta `s` segundos y lanza `queue.Empty` si no llega nada | item |
| `threading.Lock()` + `with lock:` | *Mutex*: solo un thread a la vez ejecuta el bloque | — |
| `dataclasses.replace(obj, **cambios)` | Copia de un dataclass con algunos campos cambiados | nuevo objeto |
| `threading.Timer(s, fn)` | Thread que llama `fn()` después de `s` segundos (`--duration`) | `Timer` |

### `match` (structural pattern matching, Python 3.10+)
`Core.handle` usa `match evento:` con `case StartFocus(minutes=m, mode=md):`. Cada `case` compara
la **clase** del objeto y extrae atributos en variables. Es un `if isinstance(...)` más legible.

### Comandos (`events.py`)
`StartFocus(minutes, mode)`, `StopFocus()`, `SetCameraPaused(paused)`, `PauseAll(minutes)`,
`FalseAlarm()`, `ReloadClassifier()`: dataclasses inmutables que el tray y el dashboard publican.
`Command = StartFocus | StopFocus | ...` es un *type alias* con la unión de todos.

### `LiveState`
El core escribe con `live.update(campo=valor)` y la UI lee con `live.snapshot()`. El `Snapshot` es
`frozen`: quien lo lee recibe una foto que nadie más puede modificar.

## 2. Señales (Ctrl+C, SIGTERM) con el tray

| API | Qué hace | Retorna |
|---|---|---|
| `signal.signal(signum, handler)` | Registra `handler(signum, frame)`. Python lo ejecuta en el main thread **cuando éste corre código Python** | handler anterior |
| `PyObjCTools.MachSignals.signal(signum, handler)` | Igual, pero la señal llega como un mensaje al **run loop de Cocoa**, así funciona aunque el main thread esté dentro de él. `handler(signum)` recibe solo el número | handler anterior |
| `PyObjCTools.MachSignals.getsignal(signum)` | Handler registrado | handler o `None` |

Sin tray, `run_main_loop` ejecuta Python cada 0,25 s, así que basta `signal.signal`. Con tray, el
run loop de Cocoa no ejecuta Python, y pystray instala un handler de SIGINT que llama
`NSApplication.terminate_` (cierra el proceso sin pasar por nuestro `finally`). Por eso el tray
lo reemplaza con MachSignals por uno que solo activa `stop` (DECISIONS.md #59; bug encontrado al
probar la app real).

## 3. System tray — pystray + Pillow

| API (`pystray`) | Qué hace | Argumentos / Retorna |
|---|---|---|
| `pystray.Icon(name, icon, title, menu)` | Crea el ícono de la barra de menú | `icon`: imagen Pillow; `title`: tooltip |
| `icon.run(setup=fn)` | **Bloquea el main thread** con el loop de la UI; llama `fn(icon)` en otro thread cuando el ícono está listo | `None` |
| `icon.visible = True` | Muestra el ícono (dentro de `setup`) | — |
| `icon.icon = imagen` / `icon.title = texto` | Cambia la imagen / el tooltip | — |
| `icon.update_menu()` | Vuelve a evaluar textos y visibilidad del menú | `None` |
| `icon.stop()` | Termina `run()` | `None` |
| `pystray.Menu(*items)` / `pystray.Menu.SEPARATOR` | Menú / línea divisoria | `Menu` |
| `pystray.MenuItem(text, action, enabled=..., visible=...)` | Ítem. `text`, `enabled` y `visible` aceptan valores o funciones `f(item)` que se evalúan al abrir el menú; `action` se llama al hacer click (puede no recibir argumentos) | `MenuItem` |

| API (Pillow, `PIL`) | Qué hace | Retorna |
|---|---|---|
| `Image.new("RGBA", (64, 64), (0, 0, 0, 0))` | Imagen nueva con fondo transparente (RGBA = rojo, verde, azul, alpha) | `Image` |
| `ImageDraw.Draw(image)` | Objeto para dibujar sobre la imagen | `ImageDraw` |
| `draw.ellipse((x0, y0, x1, y1), fill=color, outline=color)` | Círculo/elipse dentro de ese rectángulo | `None` |
| `image.getpixel((x, y))` | Color de un pixel (tests) | `tuple` |

Nuestras funciones (`ui/tray.py`), testeadas sin abrir el tray:
- `icon_color(snapshot, now)`: verde = FOCUSED (o app productive sin cámara), amarillo =
  distraído (o app distracting), gris = pausado/ausente/neutral.
- `make_icon(color, camera_on)`: círculo + punto rojo si la cámara está encendida (FR-71).
- `status_lines(snapshot, now)`: líneas del menú (focus, cámara, app, timers del día — FR-20).

`webbrowser.open(url)` (stdlib) abre la URL en el navegador por defecto ("Abrir dashboard").

## 4. Dashboard — FastAPI + Jinja2 + uvicorn

**FastAPI** define una API web con funciones Python decoradas; usa los type hints para validar.

| API | Qué hace |
|---|---|
| `FastAPI(title=..., docs_url=None, ...)` | Crea la app (sin páginas de documentación automática) |
| `@app.get("/ruta", response_class=HTMLResponse)` / `@app.post(...)` | Registra la función para ese método HTTP (*HyperText Transfer Protocol*) y ruta |
| `Annotated[str, Form(min_length=1)]` | El parámetro viene de un formulario HTML; FastAPI lo valida (si falla → 422). Necesita `python-multipart` |
| `Annotated[Literal["BORRAR"], Form()]` | Solo acepta exactamente ese texto |
| `Depends(fn)` / `dependencies=[Depends(fn)]` | *Dependency injection* de FastAPI: corre `fn(request)` antes del endpoint (el chequeo de origen) |
| `Request` | La request HTTP: `request.headers.get("origin")` |
| `HTTPException(status_code, detail)` | Corta la request con ese código de error (403, 409…) |
| `RedirectResponse("/", status_code=303)` | Redirección; 303 hace que el navegador pida la página con GET (patrón Post/Redirect/Get) |
| `app.add_middleware(TrustedHostMiddleware, allowed_hosts=[...])` | *Middleware* (código que envuelve cada request) que rechaza (400) los `Host` que no sean locales |
| `urllib.parse.urlparse(url).hostname` | Separa una URL en partes; aquí, el host del header `Origin` |

**Jinja2** genera el HTML desde plantillas (`dashboard/templates/`):

| API / sintaxis | Qué hace |
|---|---|
| `Jinja2Templates(directory=...)` | Carga las plantillas |
| `TEMPLATES.TemplateResponse(request, "today.html", contexto)` | Renderiza la plantilla con las variables del `dict` → `HTMLResponse` |
| `TEMPLATES.env.filters["duration"] = format_duration` | Filtro propio: `{{ segundos \| duration }}` |
| `{% extends "base.html" %}` + `{% block content %}` | Herencia: `today.html` rellena los bloques de `base.html` |
| `{{ variable }}`, `{% for x in lista %}…{% else %}…{% endfor %}`, `{% if %}`, `{% set x = … %}` | Imprimir (escapando HTML), iterar (`else` = lista vacía), condicionales, variables |

**uvicorn** es el servidor ASGI (*Asynchronous Server Gateway Interface*) que atiende las requests:

| API | Qué hace |
|---|---|
| `uvicorn.Config(app, host="127.0.0.1", port=8765, log_level="warning")` | Configuración. `127.0.0.1` = solo accesible desde este computador (nunca `0.0.0.0`) |
| `uvicorn.Server(config)` + `server.run()` | Corre el servidor (bloquea); lo lanzamos en un thread (`DashboardServer.start`) |
| `server.should_exit = True` | Pide cerrar limpio (`DashboardServer.stop`) |
| `uvicorn.run(app, host=..., port=...)` | Atajo bloqueante (`nublock dashboard`) |

Seguridad (DECISIONS.md #61): **DNS rebinding** = un sitio malicioso hace que su dominio apunte a
`127.0.0.1` para hablar con tu dashboard → lo bloquea `TrustedHostMiddleware`. **CSRF**
(*Cross-Site Request Forgery*) = otra página envía un formulario a `http://127.0.0.1:8765` →
el navegador agrega el header `Origin` de esa página y lo rechazamos con 403.

Páginas y datos (`dashboard/data.py`):
- `build_today(repository, day, now) -> TodayView`: reporte del día, bloques del timeline
  (posición/ancho en % del día), apps `uncategorized`, distracciones físicas (eventos LOOKING_AWAY /
  LOOKING_DOWN / PHONE), refocus promedio (`statistics.mean`), falsas alarmas, focus sessions.
- `build_week(repository, last_day) -> list[DayTotals]`: totales por productivity de 7 días.
- Endpoints: `GET /`, `GET /week`, `GET /api/today` (JSON), `POST /classify`, `/focus/start`,
  `/focus/stop`, `/camera`, `/pause`, `/feedback/false-alarm`, `/data/delete`.

### Tests con `fastapi.testclient.TestClient`
`TestClient(app, base_url="http://127.0.0.1:8765")` llama a la app **en memoria**, sin abrir un
puerto (usa la librería `httpx`). `client.get(url)` / `client.post(url, data={...},
headers={...}, follow_redirects=False)` retornan una respuesta con `.status_code`, `.text` y
`.json()`.
