# M6 — Blocking y modo strict (+ export de datos)

**Objetivo:** que las reglas no solo avisen sino que se cumplan, y que desactivarlas en modo strict
cueste algo (un *commitment device*: un mecanismo que uno se impone para cumplir una meta). DoD:
superar `social-daily-limit` cierra o minimiza la app. Verificado con la app real: una regla
`block` de 6 s ocultó la Calculadora a los 6 s de uso.

| Archivo | Qué contiene |
|---|---|
| `src/nublock/tracker/platform/base.py` | Interfaz `AppBlocker` (`hide`, `terminate`) |
| `src/nublock/tracker/platform/macos.py` | `MacOSAppBlocker` |
| `src/nublock/tracker/platform/fake.py` | `FakeAppBlocker` (tests) |
| `src/nublock/blocking.py` | `Enforcer`: decide ocultar o cerrar, protege apps del sistema |
| `src/nublock/friction.py` | `FrictionGate`: esperar 60 s + escribir la frase |
| `src/nublock/core.py` | Acciones `block`/`warn`, bloqueo en focus sessions, comandos con `confirmed` |
| `src/nublock/rules/engine.py` | `current_violations`, `disable(rule_id, until)` |
| `src/nublock/dashboard/server.py` + `templates/friction.html` | Reglas, fricción, export |
| `tests/test_blocking.py`, `test_core_blocking.py`, `test_dashboard_m6.py` | Tests |

Cómo probarlo manualmente (`observe_only: false` en tu config):

```yaml
rules:
  - { id: prueba, type: daily_limit, target: { process: Calculator }, limit_minutes: 0.2,
      action: block, mode: soft }
```

1. `python -m nublock run`, abre la Calculadora (`open -a Calculator`) y úsala 12 s → se oculta.
2. Cambia `mode: strict` → se cierra. Prueba `action: warn` con `grace_seconds: 10`.
3. Dashboard → "Reglas" → "Desactivar hoy": una regla soft se desactiva al instante; una strict te
   lleva a la página de confirmación (cuenta regresiva + frase).
4. Inicia una focus session strict desde el tray e intenta terminarla: abre la misma página.
5. Exporta: `http://127.0.0.1:8765/export.csv?days=7`.

## 1. Ocultar y cerrar apps en macOS — `NSRunningApplication`

| API (AppKit, vía pyobjc) | Qué hace | Retorna |
|---|---|---|
| `NSRunningApplication.runningApplicationWithProcessIdentifier_(pid)` | La app que corre con ese PID | `NSRunningApplication` o `None` |
| `app.hide()` | Oculta la app (como Cmd+H): sigue abierta pero sale de la pantalla | `bool` (no confiable: puede decir `False` aunque la oculte) |
| `app.terminate()` | Le pide a la app que se cierre (como Cmd+Q); puede preguntar si guardar | `bool` (si se envió la petición) |
| `app.isHidden()` / `app.isTerminated()` | Estado actual (usado en las pruebas) | `bool` |

¿Por qué ocultar y no minimizar? Minimizar ventanas de *otra* app requiere el permiso
**Accessibility** (controlar el computador); ocultar no requiere permisos.

## 2. `Enforcer` (`blocking.py`)

**`Enforcer(blocker, config, own_pid=None)`** y **`enforce(window, strict, now) -> "hide" | "terminate" | None`**:
- soft → `hide`; strict → `terminate`, salvo los procesos de `blocking.never_terminate`
  (browsers), que solo se ocultan.
- Nunca toca `PROTECTED` (Finder, loginwindow, Dock, …) ni a Nublock (`os.getpid()` = PID del
  proceso actual).
- Máximo una acción cada 2 s por app (`MIN_INTERVAL`), para no insistir en cada tick.
- `Literal["hide", "terminate"]`: el tipo de retorno solo puede ser esos dos strings (o `None`).

## 3. Acciones de las reglas (FR-22) — `Core`

En cada `ActivityEvent`, después de `RulesEngine.evaluate()` (que avisa solo al *entrar* en
violación), `Core._enforce_rules()` revisa `rules.current_violations` (las reglas violadas *ahora*):

| `action` | Qué pasa |
|---|---|
| `notify` | Solo la notificación |
| `warn` | Notificación "Tienes N s para salir"; si sigues en la app al vencer `grace_seconds` → bloqueo. Salir antes lo cancela |
| `block` | Notificación + bloqueo inmediato; si reabres la app, se vuelve a bloquear |

Con `observe_only: true` o "Pausar todo" no se bloquea nada. Durante una focus session con
`block_distracting`, las apps `distracting` se bloquean igual (la focus session es un pedido
explícito). Cada bloqueo queda en `interventions` con `trigger = "block:<motivo>"`.

`dict.setdefault(key, valor)`: si `key` no existe la guarda con `valor`; en ambos casos retorna lo
guardado. Así el plazo de `warn` se fija la primera vez y no se reinicia en cada tick.

## 4. Fricción del modo strict (FR-23)

**Qué la exige**: pausar todo (si hay reglas strict activas o una focus session strict), terminar
una focus session strict y desactivar una regla strict. Pausar la cámara **nunca** (privacidad).

Flujo: el dashboard (o el tray) redirige a `GET /friction?action=...` → `FrictionGate.request()`
crea una solicitud con un token → la página muestra una cuenta regresiva y la frase → `POST
/friction/confirm` → `FrictionGate.confirm(token, frase)`:

| Resultado | Cuándo |
|---|---|
| `wait_seconds > 0` | Todavía no pasan los 60 s |
| `error="La frase no coincide."` | Frase distinta (se ignoran espacios al inicio/fin) |
| `error="...expiró."` | Token desconocido, ya usado o de hace más de 10 min |
| `ok=True` | Se publica el comando con `confirmed=True` |

Defensa en profundidad: el **Core** rechaza `PauseAll`, `StopFocus` y `DisableRule` sin
`confirmed=True` cuando aplica strict. Saltarse la página no sirve.

| API | Qué hace | Retorna |
|---|---|---|
| `secrets.token_urlsafe(12)` | Texto aleatorio criptográficamente seguro (no se puede adivinar) | `str` |
| `threading.Lock()` | `FrictionGate` lo usa porque cada request del dashboard puede correr en un thread distinto | — |
| `onpaste="return false"` (HTML) | Impide pegar en el campo: la frase hay que escribirla | — |
| `setInterval(fn, 1000)` (JavaScript, inline) | Actualiza la cuenta regresiva cada segundo. Es solo visual: el servidor valida el tiempo | id del timer |

**`disable_events`** (tabla nueva): cada pausa/desactivación queda registrada; el dashboard
muestra "veces que desactivaste algo" hoy y en 7 días.

## 5. Export (FR-62)

`GET /export.json?days=7` y `GET /export.csv?days=7` (1–365 días): una fila por día, app,
categoría e idle con los segundos. **Nunca** incluye títulos de ventana.

| API | Qué hace | Retorna |
|---|---|---|
| `Annotated[int, Query(ge=1, le=365)]` (FastAPI) | Parámetro de la URL (`?days=`) validado | `int` |
| `io.StringIO()` | Un "archivo" de texto en memoria | objeto tipo archivo |
| `csv.DictWriter(archivo, fieldnames=...)` + `.writeheader()` + `.writerows(filas)` | Escribe dicts como CSV (*Comma-Separated Values*) con encabezado | `None` |
| `Response(contenido, media_type="text/csv", headers={"Content-Disposition": "attachment; ..."})` | Respuesta HTTP; `attachment` hace que el navegador lo descargue como archivo | `Response` |
| `dict(zip(campos, valores, strict=True))` | Arma un dict a partir de dos secuencias del mismo largo | `dict` |
