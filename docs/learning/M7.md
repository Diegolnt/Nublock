# M7 — Bloqueo de sitios con /etc/hosts (sin extensión de browser)

**Objetivo:** que YouTube, Instagram, etc. no carguen cuando una regla, una focus session o tu
lista `always` lo indican, en **todos** los browsers y apps. (El PRD proponía una extensión de
browser; elegimos bloquear por DNS a nivel de sistema, ver DECISIONS.md #91–98.)

| Archivo | Qué contiene |
|---|---|
| `src/nublock/site_blocking.py` | Script del helper, plist, `SiteBlocker`, `install()`/`uninstall()` |
| `src/nublock/config.py` | `SiteConfig` (dominio + categoría), `SiteBlockingConfig` |
| `src/nublock/rules/engine.py` | `condition_met()`: ¿la regla está activa, sin importar la app? |
| `src/nublock/core.py` | `blocked_sites(now)`: qué dominios bloquear ahora |
| `tests/test_site_blocking.py` | Ejecuta el script real del helper sobre archivos temporales |

Cómo probarlo:

```bash
python -m nublock sites setup     # una vez: macOS pide tu contraseña de administrador
python -m nublock run             # inicia una focus session desde el tray
python -m nublock sites status    # -> bloqueados ahora: instagram.com, youtube.com, ...
curl -sI https://www.youtube.com  # falla: el dominio apunta a 0.0.0.0
grep -A20 nublock /etc/hosts      # la sección que escribe el helper
python -m nublock sites remove    # desinstalar (deja /etc/hosts como estaba)
```

---

## 1. DNS y /etc/hosts

Para abrir `youtube.com`, el computador primero pregunta su IP (*DNS*, Domain Name System). Antes
de preguntarle a internet, macOS revisa `/etc/hosts`, un archivo de texto con líneas
`IP nombre`. Si dice `0.0.0.0 youtube.com`, la conexión va a una dirección que no existe y el
sitio no carga. `::` es lo mismo para IPv6. No sirve bloquear por IP: los sitios grandes
comparten IPs con otros servicios y las cambian seguido.

`/etc/hosts` no tiene comodines: `youtube.com` no bloquea `www.youtube.com`. Por eso
`expand_domains()` agrega `www.`, `m.` y `mobile.`.

## 2. Por qué un helper de root (y cómo es seguro)

`/etc/hosts` pertenece a root (el administrador del sistema). Para no pedir la contraseña cada vez
que cambia la lista, se instala una vez:

```
/Library/PrivilegedHelperTools/local.nublock.hosts.sh    (root, 755)  el script
/Library/LaunchDaemons/local.nublock.hosts.plist         (root, 644)  cuándo correrlo
/Library/Application Support/Nublock/                    (root, 755)  carpeta
    blocked_domains.txt                                  (tu usuario)  la lista que escribe Nublock
```

**launchd** es el sistema de macOS que arranca procesos. Un **LaunchDaemon** corre como root;
con `WatchPaths`, launchd lo ejecuta cada vez que cambia el archivo vigilado. Es decir, Nublock
escribe la lista → launchd corre el script como root → el script actualiza /etc/hosts.

Por qué no es una puerta trasera:
- El script y el plist son de root: tu usuario (o un programa malicioso con tus permisos) no
  puede cambiar *qué* ejecuta root.
- El script solo acepta líneas que son dominios válidos (regex) y solo escribe `0.0.0.0`/`::`.
  Lo peor que podría hacer alguien con tu usuario es *bloquear* dominios.
- Ignora la lista si es un symlink, y la carpeta es de root: nadie puede reemplazar el archivo
  por un enlace a un archivo privado del sistema.
- Solo toca su sección, entre `# >>> nublock ... >>>` y `# <<< nublock <<<`.

## 3. Herramientas del script (POSIX `sh`)

| Comando | Qué hace |
|---|---|
| `set -eu` | Termina ante cualquier error (`-e`) o variable no definida (`-u`) |
| `[ -f "$X" ]`, `[ -L "$X" ]` | ¿Es un archivo normal? ¿Es un symlink? |
| `mktemp DIR/.hosts.nublock.XXXXXX` | Crea un archivo temporal con nombre único (la X se reemplaza) |
| `trap 'rm -f "$TMP"' EXIT` | Borra el temporal al salir, pase lo que pase |
| `awk '$0 == b {skip=1; next} ...'` | Copia /etc/hosts saltándose la sección anterior de Nublock |
| `grep -E 'regex' archivo` | Solo las líneas que son dominios válidos |
| `cmp -s A B` | ¿Son iguales? (si lo son, no se toca /etc/hosts) |
| `mv TMP /etc/hosts` | Reemplazo atómico: nadie ve el archivo a medio escribir |
| `dscacheutil -flushcache; killall -HUP mDNSResponder` | Vacía el caché de DNS de macOS para que el cambio aplique ya |

## 4. Instalación desde Python

| API | Qué hace | Retorna |
|---|---|---|
| `osascript` + `do shell script ... with administrator privileges` | Ejecuta un comando como root mostrando el diálogo de contraseña de macOS | salida del comando |
| `install -o root -g wheel -m 755 origen destino` | Copia un archivo fijando dueño, grupo y permisos en un paso | — |
| `launchctl bootstrap system plist` / `bootout system/<label>` | Carga / descarga un LaunchDaemon | — |
| `shlex.quote(texto)` | Cita un texto para el shell (rutas con espacios, sin inyección de comandos) | `str` |
| `pwd.getpwuid(os.getuid()).pw_name` | El nombre de tu usuario (dueño de la lista) | `str` |
| `os.access(ruta, os.W_OK)` | ¿Puedo escribir ese archivo? | `bool` |

## 5. Qué se bloquea (`Core.blocked_sites`)

Para cada sitio de `sites:` en el config:

| Se bloquea si… | Ejemplo |
|---|---|
| `always: true` | un sitio que nunca quieres abrir mientras Nublock corre |
| hay una focus session y el sitio es `distracting` | YouTube durante tu sesión de 50 min |
| una regla `block`/`warn` está activa y su target coincide con la categoría del sitio | pasaste los 30 min de `social` → instagram.com, tiktok.com, x.com |

"Activa" la decide `condition_met(rule, timers, now)`: límite diario superado o dentro del
horario. A diferencia de `RulesEngine.evaluate`, no exige que la app activa coincida: el sitio se
bloquea aunque ahora estés en otra app. "Pausar todo" libera todo; al cerrar Nublock también.

`SiteBlocker.apply(dominios)` escribe la lista **solo si cambió** (cada escritura despierta a
launchd). Un target con `process` nunca aplica a un sitio, porque un sitio no es un proceso.

## 6. Límites (frente a una extensión)

- Bloquea dominios completos, no rutas (`youtube.com/shorts`).
- No mide tiempo por sitio: el tiempo en YouTube dentro de Chrome se atribuye por el título de la
  ventana (necesita el permiso Screen Recording).
- Una pestaña ya abierta puede seguir ~1 min (caché de DNS del browser, conexiones abiertas).
- Como administrador siempre puedes editar /etc/hosts: es un commitment device, no un candado.
