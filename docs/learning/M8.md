# M8 — Nublock como app de macOS: arranque, permisos y onboarding

**Objetivo:** usar Nublock sin terminal: una app que se abre desde Spotlight o al iniciar
sesión, con los permisos a su nombre, y un comando que diga qué falta. (El DoD del PRD, "instalar
en un PC limpio", queda a medias: ver DECISIONS.md #107.)

| Archivo | Qué contiene |
|---|---|
| `src/nublock/interventions/macos_app/Nublock.swift` | La app: launcher/supervisor, notificaciones, permisos, login item |
| `src/nublock/interventions/app_bundle.py` | `build_app()`, `info_plist()`, `run_app()` (vía `open`) |
| `src/nublock/instance.py` | `InstanceLock`: una sola instancia de `nublock run` |
| `src/nublock/doctor.py` | `run_checks()`, `format_checks()`, `fix_permissions()` |
| `src/nublock/autostart.py` | LaunchAgent de respaldo para abrir al iniciar sesión |
| `tests/test_m8_app.py` | Tests (el supervisor Swift se probó con un "Python" falso) |

Cómo probarlo:

```bash
python -m nublock app install
python -m nublock doctor --fix     # responde los diálogos: "Nublock quiere acceder a la cámara"
open -a Nublock                    # aparece el ícono en la barra de menú
open -a Nublock                    # otra vez: no se duplica (abre el dashboard)
python -m nublock app autostart-on # opcional
```

## 1. ¿Por qué una app? El proceso "responsable"

macOS decide los permisos de privacidad (TCC, *Transparency, Consent and Control*) mirando al
**proceso responsable**: la app que inició la cadena de procesos.

```
iTerm2 ──> python -m nublock run          responsable: iTerm2   (permisos de iTerm2)
Nublock.app ──> python -m nublock run     responsable: Nublock  (permisos de Nublock)
```

Medido en esta sesión: el binario de la app ejecutado *directo desde la terminal* reportó
`camera: granted` (el permiso de iTerm2); abierto con `open` reportó `not_determined` (el de
Nublock). Por eso `doctor` usa `run_app()`, que ejecuta `open -W -n -g --stdout … -a Nublock.app
--args …`:

| Opción de `open` | Qué hace |
|---|---|
| `-a App.app` | Abre esa app (vía LaunchServices: macOS la trata como app propia) |
| `-W` | Espera a que la app termine |
| `-n` | Abre una instancia nueva aunque ya haya una corriendo |
| `-g` | En segundo plano (no la trae al frente) |
| `--stdout` / `--stderr archivo` | Dónde escribe la app su salida |
| `--args …` | Argumentos para la app |

## 2. El launcher en Swift

| API (Foundation / AppKit) | Qué hace |
|---|---|
| `Process()` + `.executableURL`, `.arguments`, `.currentDirectoryURL` | Configura un proceso hijo (el Python del venv, `-m nublock run`, desde tu home) |
| `.standardOutput` / `.standardError = FileHandle` | Redirige su salida a `~/Library/Logs/nublock/app.log` |
| `.terminationHandler = { proceso in … }` | Se llama cuando el hijo termina; `terminationStatus` es su exit code |
| `try process.run()` / `.terminate()` / `.isRunning` | Iniciar / enviar SIGTERM / ¿sigue vivo? |
| `Bundle.main.object(forInfoDictionaryKey:)` | Lee claves del Info.plist (`NublockPython`, `NublockDashboard`) |
| `applicationWillTerminate(_:)` | Al cerrar la app (ej. cerrar sesión) se detiene el hijo con SIGTERM |

Reglas del supervisor (`childExited`):

| Exit code del hijo | Qué hace la app |
|---|---|
| 0 | Elegiste "Salir" en el tray → la app termina |
| 3 | Ya había otra instancia → abre el dashboard y termina |
| otro | Se cayó → reintenta a los 5 s (máx. 5 veces en 10 min) |

Permisos (`--status`, `--request-permissions`):

| API | Qué hace | Retorna |
|---|---|---|
| `UNUserNotificationCenter.getNotificationSettings` | Estado del permiso de notificaciones | `.authorized`, `.denied`, `.notDetermined`… |
| `AVCaptureDevice.authorizationStatus(for: .video)` / `.requestAccess(for:)` | Estado / pedir permiso de cámara (framework AVFoundation) | estado / `Bool` en el closure |
| `CGPreflightScreenCaptureAccess()` / `CGRequestScreenCaptureAccess()` | Consultar / pedir Screen Recording (CoreGraphics) | `Bool` |
| `SMAppService.mainApp.register()` / `.status` | Abrir la app al iniciar sesión (ServiceManagement, macOS 13+) | lanza error / estado |
| `JSONSerialization.data(withJSONObject:)` | Diccionario → JSON (lo lee `doctor`) | `Data` |
| `DispatchSemaphore` | Espera a que termine un callback asíncrono (con timeout) | — |

`NSCameraUsageDescription` (Info.plist) es **obligatorio**: sin ese texto, macOS no permite usar la
cámara a ningún proceso de la app.

## 3. Instancia única — `fcntl.flock`

| API | Qué hace |
|---|---|
| `fcntl.flock(fd, fcntl.LOCK_EX \| fcntl.LOCK_NB)` | Lock exclusivo del OS sobre un archivo; `LOCK_NB` = si otro lo tiene, lanza `BlockingIOError` en vez de esperar |
| `fcntl.flock(fd, fcntl.LOCK_UN)` | Libera el lock |

El lock vive mientras el proceso tenga el archivo abierto: si Nublock se cae, el OS lo libera solo.
`InstanceLock.held_by_other()` lo usa `doctor` para saber si Nublock está corriendo.

## 4. Arranque al iniciar sesión (FR-73)

1. `SMAppService.mainApp.register()` → aparece en System Settings → General → Login Items.
2. Si macOS no lo acepta (puede pasar con apps firmadas ad-hoc), un **LaunchAgent**: un plist en
   `~/Library/LaunchAgents/local.nublock.autostart.plist` que launchd ejecuta al iniciar sesión
   (`RunAtLoad`): `/usr/bin/open -a ~/Applications/Nublock.app`.

| Comando | Qué hace |
|---|---|
| `launchctl bootstrap gui/<uid> plist` | Carga el agente en tu sesión gráfica |
| `launchctl bootout gui/<uid>/<label>` | Lo descarga |

## 5. `nublock doctor`

`run_checks()` retorna una lista de `Check(name, ok, detail, fix, optional)`; `format_checks()` los
muestra con ✓ (ok), ✗ (falta, obligatorio) o · (opcional), y la acción sugerida. `--fix` llama
`fix_permissions()`: ejecuta la app con `--request-permissions` (diálogos de macOS a nombre de
Nublock) y abre con `open x-apple.systempreferences:…` el panel de cada permiso que siga faltando.

## 6. La ventana de permisos (AppKit)

`OnboardingWindow` en `Nublock.swift`, construida en código (sin Interface Builder):

| API (AppKit) | Qué hace |
|---|---|
| `NSWindow(contentRect:styleMask:backing:defer:)` | Crea la ventana (`.titled`, `.closable`) |
| `NSStackView` (`orientation`, `alignment`, `spacing`, `edgeInsets`, `addArrangedSubview`) | Apila vistas en fila o columna y se ajusta solo (Auto Layout) |
| `NSTextField(labelWithString:)` / `(wrappingLabelWithString:)` | Texto fijo de una línea / con saltos de línea |
| `NSButton(title:target:action:)` + `#selector(act(_:))` | Botón que llama a un método; `identifier` dice de qué fila es |
| `NSImageView` + `NSImage(systemSymbolName:)` + `contentTintColor` | Íconos SF Symbols (✓ verde, ○ gris, ✗ rojo) |
| `Timer.scheduledTimer(withTimeInterval: 1, repeats: true)` | Actualiza los estados cada segundo |
| `NSWindowDelegate.windowWillClose(_:)` | Al cerrar: guarda que ya se mostró (`UserDefaults`) y avisa al launcher |
| `NSApp.activate(ignoringOtherApps:)` + `makeKeyAndOrderFront` | Trae la ventana al frente (la app no tiene ícono en el Dock) |
| `bitmapImageRepForCachingDisplay(in:)` + `cacheDisplay(in:to:)` | Dibuja la vista a una imagen (`--snapshot`) |

Cada botón hace lo mismo que harías a mano: `requestAuthorization` (notificaciones),
`AVCaptureDevice.requestAccess` (cámara), `CGRequestScreenCaptureAccess` (pantalla), o
ejecuta `python -m nublock calibrate --gui` / `sites setup` como proceso hijo (así la cámara y el
diálogo de administrador quedan a nombre de Nublock). Si un permiso fue negado, el botón dice
"Abrir Ajustes" y abre el panel de System Settings correspondiente.

## 7. Calibración en una ventana — `run_calibration_gui`

Bucle de OpenCV: leer frame → analizar la cara → dibujar instrucciones → `cv2.imshow` →
`cv2.waitKey(1)` (ESPACIO = 32, Esc = 27). `cv2.flip(img, 1)` voltea la imagen horizontalmente
(efecto espejo). Al medir cada punto junta 2 s de `(yaw, pitch)` y al final llama
`compute_zone`, igual que la versión de terminal.

## 8. Distribuir sin Apple: `scripts/build_release.py` + `install.sh`

```
build_release.py:
  1. descarga CPython relocatable (python-build-standalone) y verifica su SHA-256
  2. build_app(..., python=None)          -> Nublock.app sin NublockPython (modo release)
  3. tarfile.extractall(..., filter="data") -> Contents/Resources/python
  4. python3 -m pip install <repo>        -> Nublock + dependencias dentro de la app
  5. modelos + config.example.yaml        -> Contents/Resources
  6. codesign --force --deep --sign -      -> firma ad-hoc de todo el bundle
  7. ditto -c -k --keepParent             -> dist/Nublock-<versión>-macos-<arch>.zip (+ .sha256)
```

| API / herramienta | Qué hace |
|---|---|
| `curl -fL --progress-bar -o archivo url` (vía `subprocess.run`) | Descarga un archivo. No usamos `urllib`: el Python de python.org no usa los certificados de macOS y falla con `CERTIFICATE_VERIFY_FAILED` |
| `hashlib.sha256()` + `.update(bytes)` + `.hexdigest()` | Huella SHA-256 de un archivo: si cambia un byte, cambia la huella |
| `tarfile.open(...).extractall(destino, filter="data")` | Descomprime un .tar.gz; `filter="data"` rechaza rutas peligrosas (`../`, links absolutos) |
| `platform.machine()` | Arquitectura: `arm64` (Apple Silicon) o `x86_64` (Intel) |
| `ditto -c -k --keepParent App.app x.zip` / `ditto -x -k x.zip carpeta` | Comprimir / descomprimir conservando permisos, symlinks y firma (mejor que `zip` para apps) |
| `xattr -dr com.apple.quarantine App.app` | Quita la marca de cuarentena (la que pone el browser al descargar) |
| `shasum -a 256 -c archivo.sha256` | Verifica que el zip descargado tenga la huella publicada |
| `curl -fsSL url \| sh` | Descarga el instalador y lo ejecuta (`-f` falla si hay error HTTP, `-sS` silencioso salvo errores, `-L` sigue redirecciones) |

**Gatekeeper y la cuarentena**: macOS bloquea las apps descargadas por el browser que no están
notarizadas por Apple. La marca la pone la app que descarga (Safari, Chrome); curl no la pone.
Por eso la instalación recomendada es `curl … | sh`.
